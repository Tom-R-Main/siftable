## Friction found and repaired

1. **CLI operation help returned unrelated global help.** `work.claim --help` and `work.artifacts.add --help` now emit input-mode JSON Schema, required fields/defaults/limits, stable-key instructions and lease-custody guidance. Help requires neither credentials nor a service. The local syntax reference is explicitly separate from live permission/module discovery through `catalog`. Six subprocess tests cover all 60 operations, unknown help, nested defaults, unavailable credential/input files and custody-field omission.
2. **MCP discovery mislabeled defaults as mandatory.** C observed that `includeDeleted`, paging and lease duration appeared required, although omitted-default calls succeeded. MCP now exports input-mode schemas. C reconnected fresh clients and verified both listing and actual omitted-default calls. Its original immutable report still records the mismatch; a correction supplement preserves the chronology.
3. **Artifact writes required a list lookup to find the new ID.** The additive `artifactId` receipt field supports direct retrieval while retaining the existing work `id`. New write receipts and events include the ID; same-key retries return the same receipt. Existing historical receipts are not rewritten. A separate linked follow-up work item records validation of this last observation, preserving the main pilot's verification history.

## Recovery drill

Root invoked the packaged admin CLI to back up the real project while B held an active epoch-2 lease, verify the archive, and restore into a new database `siftable_pilot_20261116`. A temporary server exposed that database only at loopback port 8089. The original database and endpoint were not switched or overwritten.

- The restore verified all **23 owned tables and 96 snapshot rows**, including definitions, records, evidence, artifacts, receipts and module state.
- An API comparison independently matched project/note content, plan/history prefix, dependencies, links, evidence and full artifact contents. Restored work was queued at epoch 3, with an explicit `restore.lease_invalidated` event and no active expiry.
- B retried its exact original claim key on the restored endpoint. It received the historical epoch-2 receipt, as durable idempotency requires. A new heartbeat using that saved old lease failed; recovered work stayed queued at epoch 3. Historical success is not current lease authority.
- C made a fresh recovered claim at epoch 4 and continued through MCP and CLI. It separately claimed the source at epoch 3 and appended its report/evidence there. Old failed evidence remained available.
- No SQL row edits or original-database reset were needed. Root used supported backup/restore administration plus protected credential/endpoint configuration for the temporary server.

The drill archive is privately retained at `.local/pilot-20261116/backup/`; its SHA-256 is `491bc2c5b7f5209b9accb4ed879f35b3178087ce5f70c6c7b3b2006c5c3b7457`. Private bootstrap/configuration and operational receipts stay under `.local/pilot-20261116/` and are not tracked. The restored database is a verification branch, never a second execution authority.
